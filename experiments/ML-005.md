# ML-005 — Bar-based Mamba-2 versus PatchTST

**Status:** Open for research/implementation. **Upstreams:** https://github.com/state-spaces/mamba and https://github.com/yuqinie98/PatchTST

## Question

At matched approximate parameter count, number of past bars and training budget, does a state-space sequence architecture (Mamba) or a patch-based Transformer (PatchTST) add stable trade-outcome information?

## Plan

1. Construct a compact shared tensor input from completed OHLCV bars plus optional causal 5/15-minute context. Do not use event/order-book/DOM data.
2. Implement thin adapters behind `ProbabilisticTradeModel`; document optional PyTorch and Mamba build requirements without making the core harness heavy.
3. Unit-test shape, contiguous sessions, feature causality, and serialization. Use synthetic data for compute smoke checks, not profit claims.
4. Design time-ordered train/validation/test data with overlapping labels purged and contract gaps handled. Compare plain-feature baseline, PatchTST and Mamba using common opportunities, costs and seeds.
5. Report training time, inference latency, reproducibility across seeds, calibration, after-cost net R when real data are legitimately available, and reasons for any discarded architecture.

## Stop

No after-cost incremental improvement versus simple baselines => stop instead of doubling the network size.
