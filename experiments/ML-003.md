# ML-003 — Kronos candle-token transfer

**Status:** Open. **Upstream:** https://github.com/shiyu-coder/Kronos

## Question

Do Kronos' tokenized-candlestick sequence representations or probabilistic future paths help classify 1-minute or 5-minute NQ candidate outcomes versus plain causal bars and a small sequence model?

## Plan

1. Audit the Kronos tokenizer, supported frequency, scaling, small checkpoint, license, architecture and training-history disclosure.
2. Implement **one** small frozen model adapter over synthetic bar windows only; mask or reset at data gaps and contract boundaries.
3. Clearly specify whether using embeddings, token logits, or a pre-defined path forecast statistic. Fix the decision timestamp, forecast samples and horizon prior to evaluation.
4. Supply a unit test changing all bars after the decision close and verifying identical features/predictions. Add shape/finite tests.
5. For a later authorized evaluator: comparable candidate set, training-only downstream head, chronological splits, fees/slippage and reporting of incremental net R and calibration.

## Disconfirmation

If timestamp/token handling is not reproducible, if pretraining source data invalidate a clean test, or if frozen outputs do not beat simple bar controls on new periods, do not scale to bigger checkpoints.
