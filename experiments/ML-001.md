# ML-001 — Multi-head triple-barrier trade selector

**Status:** Open. **Prerequisites:** the synthetic interface is implemented. **Data:** 1-minute OHLCV and past-only aggregated bars. **Goal:** outperform identical candidate trades and a simple causal LightGBM/logistic baseline after fees and slippage.

## Research question

Does a model trained to predict mutually exclusive `target`, `stop` and `timeout` outcomes, plus optional MFE/MAE or time-to-hit heads, reject low-quality entries more reliably than standard features? Do not train only on next-candle direction and call it an execution strategy.

## Initial task

1. Read the reference labeler and contracts; establish conservative double-touch semantics, next-open entry and barrier distances.
2. Add **one** model head or calibrator that implements `ProbabilisticTradeModel`, with synthetic tests and clearly bounded dependency requirements. Compare with `SoftmaxBaseline` on the **same** synthetic examples for interface verification only.
3. Design a chronological purged split and a matched-candidate metric protocol for a later locally provided lawful NQ dataset. State how time-out payoff and fee/stop slippage enter expected R. Do not use the synthetic demo's output as evidence of market lift.
4. Show what adapter a private evaluator would need; never request its private code or data.

## Kill rules

If calibration is poor, candidate count collapses, or realized net gain vanishes against a simple baseline, record negative result rather than increasing model depth. Missing real market data => label **feasibility only**.

## Deliverable

A PR containing a runnable adapter, tests, baseline comparison mechanics and `submissions/ML-001-<topic>.md`.
