# ML-002 — Frozen Futures Foundation Model embeddings

**Status:** Open for architecture and input parity audit. **Upstream:** https://github.com/johnamcruz/Futures-Foundation-Model

## Question

Can the released futures-specific encoder be reproduced from strictly causal 5-minute OHLCV and does it add information beyond simple bar features for candidate ranking? The model is a research component, not a turnkey profitable strategy.

## Required first pass

1. Pin upstream commit, checkpoint/revision, license, architecture, exact input tensor/feature names, scaling, training instruments and dates, and minimum compute.
2. Reproduce feature derivation on **synthetic completed bars**. A missing or substitute pretrained input feature is an explicit blocker unless source officially supports it.
3. Implement a frozen encoder adapter producing `FeatureRow` values with the decision-close timestamp. No trained head until feature parity is established.
4. Specify a matched-candidate baseline and optional lightweight logistic/LightGBM head. Test pretrained embeddings versus plain features and random embeddings once lawful data is locally supplied.
5. Investigate pretraining overlap. Report historical evaluation overlapping the model's own training samples as a **transfer/feasibility** check, never pristine unseen confirmation.

## Stop

If exact features cannot be built from OHLCV, checkpoint/license incompatible, or incremental contribution is absent, stop and record it.

## Deliverable

Source/weights audit, feature schema, adapter or executable pseudo-interface with tests, verified commands and a submission note. No model weight binaries committed.
